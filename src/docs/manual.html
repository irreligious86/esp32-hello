02

Features

📡
Ping Sweep
Scans all 254 addresses in the subnet using ICMP ping. Non-blocking FreeRTOS implementation keeps the web UI responsive during the entire scan.
🔍
Port Scanner
Checks 16 common ports per host: FTP, SSH, Telnet, SMTP, DNS, HTTP, HTTPS, RTSP, MQTT, Node, MySQL, Flask, HTTP-alt, HTTPS-alt, SMB, RDP.
🏷️
MAC & OUI Lookup
Retrieves MAC addresses via ARP table after ping. Identifies device manufacturer using a built-in OUI database of 35 vendors including Starlink, Apple, Google, Xiaomi.
🖥️
OS Fingerprint
Guesses operating system by correlating open ports: Windows (SMB/RDP), Linux/Server (SSH+HTTP), IoT/Router (HTTP only), Linux/Unix (SSH only).
🌐
HTTP Banner
Sends a HEAD request to port 80 and reads the Server header. Reveals web server software: nginx, Apache, lighttpd, GoAhead, etc.
🔐
SSH Banner
Connects to port 22 and reads the SSH version string. Example: SSH-2.0-OpenSSH_8.4 reveals exact SSH daemon version.
💻
NetBIOS Names
Sends UDP queries to port 137 to retrieve Windows computer names. Works even without open TCP ports on Windows machines.
📧
Gmail HTML Report
Sends a fully styled HTML email report upon scan completion. Includes all findings: IPs, MACs, vendors, OS, ports, banners, and NetBIOS names.
📱
Bluetooth Control
Full BLE NUS (Nordic UART Service) implementation. Control the scanner from your phone using any BLE serial terminal app without Wi-Fi.

Web Interface Access

The scanner exposes a web interface accessible from any browser on the same network. Two methods are available simultaneously:

Method 1 — mDNS (recommended)

Works on all platforms without knowing the IP address.

http://esp32.local ← main scanner page http://esp32.local/settings ← configuration page
PlatformStatusNotes
Windows 10/11WORKSmDNS built-in
macOSWORKSBonjour built-in
Android ChromeWORKSRequires same Wi-Fi network
iOS SafariWORKSRequires same Wi-Fi network

Method 2 — Static IP

ESP32 always gets the same address regardless of network configuration.

http://192.168.1.200 ← main scanner page http://192.168.1.200/settings ← configuration page
TIP Bookmark both URLs. Use mDNS as primary, static IP as fallback if mDNS resolution fails on your network.
04

Boot Modes

Normal Boot

Press RST and release. ESP32 connects to the saved Wi-Fi network and starts the web server.

1. Press RST → release 2. RGB: WHITE (3 sec window) → BLUE (connecting) → GREEN (ready) 3. Open http://esp32.local in browser

Forced AP Mode — Switch to New Network

Use this when you want to configure a new Wi-Fi network without connecting to the existing one.

1
Press RST and release
This reboots the ESP32. Do not hold BOOT yet.
2
Immediately hold BOOT button
RGB turns WHITE — this is the 3-second window. Keep holding BOOT.
3
Hold for 3 seconds, then release
RGB turns ORANGE — AP mode is now active. You can release BOOT.
4
Connect to ESP32-Setup network
On your phone or laptop: Wi-Fi → ESP32-Setup → password: 12345678
5
Open settings page
In browser: http://192.168.4.1/settings
6
Enter new network credentials and save
Fill in SSID and password. Press Save & Reboot. ESP32 will restart and connect to the new network.
WARNING Do not press RST while holding BOOT — on ESP32-S3 this activates the firmware download mode, not our AP mode. Always: RST first → release → then hold BOOT.

Automatic AP Mode

If ESP32 cannot connect to the saved network after 5 attempts, it automatically enters AP mode. Same process — connect to ESP32-Setup with password 12345678 and open 192.168.4.1/settings.

06

Network Scanning

Press the Scan Network button on the main page to start a full subnet scan. The scan runs on CPU Core 1 (FreeRTOS) while the web UI stays responsive on Core 0.

What Gets Scanned

ESP32 pings all 254 addresses in the current subnet (e.g. 192.168.1.1 – 192.168.1.254). For each responding host:

Scan Duration

Full scan takes 15–20 minutes due to port scanning on each responding host. The radar animation and progress bar show real-time status. The page auto-refreshes every 5 seconds during scanning.

After Scan

When complete, a green glowing ✓ circle appears with scan summary. A full HTML report is automatically sent to the configured Gmail address.

NOTE ON MAC ADDRESSES Modern Android and iOS devices randomize their MAC addresses by default. This is normal — they will show as N/A or Unknown vendor. The IP address and open ports are still correctly reported.

RGB LED Indicators

The built-in WS2812B RGB LED provides visual status feedback at all times.

WHITE (steady)
Boot window — waiting for BOOT button (3 sec)
BLUE (steady)
Connecting to Wi-Fi network
GREEN (steady)
Connected and ready — web server running
ORANGE (steady)
AP mode active — ESP32-Setup network broadcasting
YELLOW (double blink)
Scanning in progress — pinging each host
RAINBOW (flash)
Device found! Brief celebration flash on discovery
GREEN (dim, steady)
Scan complete — report sent to email
RED (blinking)
Wi-Fi connection lost — attempting to reconnect

Troubleshooting

ProblemCauseSolution
Infinite reboot loop (RTC_SW_SYS_RST) Wrong platformio.ini setting Remove board_build.arduino.memory_type = qio_opi from platformio.ini
COM port not visible in Windows Missing CH340 driver Install CH341SER.exe driver
RGB LED not responding Hardcoded pin number Always use RGB_BUILTIN macro, never a raw pin number
Upload fails — port busy Serial Monitor is open Close Serial Monitor tab before pressing Upload
Can't enter bootloader — Hold BOOT → press RST → release BOOT → upload
ESP32-Setup AP not appearing BOOT pressed too early (download mode) Press RST first, RELEASE it, THEN hold BOOT for 3 sec
All MACs show N/A Randomized MAC (Android/iOS) Normal — modern devices randomize MAC by default
Email not sending Wrong app password or 2FA not enabled Generate new App Password at myaccount.google.com/apppasswords
Web UI freezes during scan Only in older single-core builds Use branch 10+ with FreeRTOS dual-core implementation
Can't reach phone from ESP32 network Starlink AP isolation Use ESP32 softAP mode or check router isolation settings
